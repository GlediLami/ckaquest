🔍 HINT 1: Observing the Problem

Let's investigate the permission denied error:

1️⃣ Check pod status:
   kubectl get pod writer-app -n volume-permissions
   kubectl logs writer-app -n volume-permissions
   
   What error message do you see?

2️⃣ Check the pod's security context:
   kubectl get pod writer-app -n volume-permissions -o yaml | grep -A 5 securityContext
   
   What user/group is the container running as?

3️⃣ Check the volume mount:
   kubectl exec writer-app -n volume-permissions -- ls -la /data 2>/dev/null || echo "Pod not running"
   
   If pod runs briefly, check what permissions the volume has

4️⃣ Look for fsGroup:
   kubectl get pod writer-app -n volume-permissions -o jsonpath='{.spec.securityContext.fsGroup}'
   
   Is fsGroup configured?

📝 Key Observation:
The container runs as user 1000, but the volume is owned by root (user 0)!
